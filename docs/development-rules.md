# 开发规则（执行版）

## 1. 总体规则

1. 单路线推进：同一需求只保留一个主方案，不并行多实现。
2. 先边界后实现：先明确作用层，再写代码。
3. 简单优先：先完成最小闭环，再做增强。
4. 默认不做旧逻辑妥协：除非明确提出兼容需求。

## 2. 分支与提交流程

1. 改代码前必须创建工作树与独立分支。
2. 一个分支只做一个目标，避免混合主题。
3. 合并前必须通过质量闸门：`check` + `build` + `test:guard`。
4. 合并后清理工作树和临时分支。

## 3. 编码规则

1. 文件职责单一：一个文件只服务一个明确责任。
2. 函数职责单一：一个函数只做一类动作（查询、校验、映射、写入）。
3. 命名中性：避免把业务实例词写死到通用层。
4. 禁止跨层快捷调用：例如页面层直接拼 SQL、API 层直接写 HTML。

## 4. 发布与安全规则

1. `/api/public/*` 只返回已发布内容，不读草稿。
2. `/api/admin/*` 必须先过 Access 校验再执行。
3. 发布动作必须事务化，不允许半成功。
4. 管理写操作必须记录审计日志。

## 5. 文档与可追踪规则

1. 任何结构性调整都要更新对应文档。
2. 发现 bug 先修复，再补守卫测试。
3. 同一问题禁止二次回归；发生回归视为流程缺陷。
